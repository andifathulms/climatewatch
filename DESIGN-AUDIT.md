# ClimateWatch — Design Audit

Factual, as-built. Describes what is in the repository at the current commit
(`7c40d57`), not what CLAUDE.md/PRD.md prescribe. Where the shipped product
diverges from those docs, the divergence is noted, not judged.

---

## 1. What this app is

Per PRD.md/CLAUDE.md: a climate intelligence platform for Indonesia, built on
Open-Meteo's free ERA5 historical weather reanalysis API (1950–present). It
lets users pick any Indonesian city and see how temperature, rainfall, and
extreme-weather patterns have changed over decades, aimed at the "curious
Indonesian public," students/researchers, journalists, farmers, city
planners, and content creators. The shipped product's own metadata renames it
"ClimateWatch" (not "Iklim," the name used throughout CLAUDE.md/PRD.md) —
`app/layout.tsx` sets the site title to "ClimateWatch — Climate Intelligence
for Indonesia" and the OG siteName to "ClimateWatch."

The core object is the **Climate Fingerprint**: a calendar-heatmap grid of
years (rows) × months (columns), one cell per month, color-encoding a chosen
climate variable (rainfall, max temperature, hot-day count, or dry-day
count). It is rendered by
[`components/fingerprint/ClimateFingerprint.tsx`](frontend/src/components/fingerprint/ClimateFingerprint.tsx),
wrapped by
[`FingerprintPanel.tsx`](frontend/src/components/fingerprint/FingerprintPanel.tsx)
(interactive controls) and previewed on the homepage in miniature,
non-interactive form by
[`FingerprintPreview.tsx`](frontend/src/components/fingerprint/FingerprintPreview.tsx).

## 2. Stack & constraints

- **Framework**: Next.js 14.2.5, App Router, TypeScript 5.5.3, React 18.3.1.
- **Build/deploy target**: dual-mode. `next.config.mjs` gates on
  `NEXT_PUBLIC_DATA_MODE`: when `"static"`, sets `output: "export"`,
  `basePath` from `NEXT_PUBLIC_BASE_PATH`, `images.unoptimized: true`, and
  `trailingSlash: true` — a fully static export for GitHub Pages
  (`metadataBase` in `layout.tsx` defaults to
  `https://andifathulms.github.io/climatewatch`). When the env var is unset,
  it runs as an ordinary server-rendered Next app against a live Django
  backend. `frontend/out/` in the repo confirms the static-export path is the
  one actually built and shipped.
- **Data layer**: [`lib/data-mode.ts`](frontend/src/lib/data-mode.ts) +
  [`lib/api.ts`](frontend/src/lib/api.ts) implement this duality explicitly —
  every API function branches on `DATA_MODE`. In `"static"` mode, reads
  pre-exported JSON files from `public/data/` (server: direct filesystem
  read; browser: `fetch`). In `"live"` mode, calls a Django REST backend at
  `NEXT_PUBLIC_API_URL` (`http://localhost:8000` default) with Next's
  `revalidate` caching (3600s for climate/regions, 900s for forecast). One
  function, `forecastContext`, always calls Open-Meteo's public forecast API
  directly regardless of mode, since the static export has no backend to
  proxy through.
- **Routing**: App Router, file-based. Routes: `/`, `/city/[slug]`,
  `/compare`, `/rankings`, `/about`, plus `sitemap.xml` and `robots.txt`
  generated by `app/sitemap.ts` / `app/robots.ts` (both `force-static`).
  `city/[slug]` uses `generateStaticParams` to pre-render one page per region
  with `has_data: true`.
- **Styling**: Tailwind CSS 3.4.6, driven entirely by CSS custom properties
  defined once in [`styles/tokens.css`](frontend/src/styles/tokens.css) and
  mapped into `tailwind.config.ts` (colors, font sizes, spacing, shadows,
  radii, easing). No `tailwind.config` color/size is a literal — every one
  resolves through `var(--token)`. Token block verbatim:

  This differs from CLAUDE.md's spec in one respect worth flagging factually:
  CLAUDE.md documents a *light* "Musim" palette (`--earth-cream: #F5F0E8`
  background, white cards). The shipped system is the dark inversion,
  labeled in-file "Musim Nokturnal," on a warm near-black canvas
  (`#12100c`), not the blue-slate dark mode CLAUDE.md warns against. There is
  one theme only — no light/dark toggle, no `prefers-color-scheme` branching
  found anywhere in the CSS.
- **Fonts**: Fraunces (display/serif headings), Inter (UI/body), JetBrains
  Mono (all numbers) — all three self-hosted via `next/font/google` in
  `app/layout.tsx`, no external `<link>`.
- **Charts**: Recharts 2.12.7 for `ExtremeDaysChart`, `SeasonShiftScatter`,
  `MonthlyBarChart`, `SeasonLengthChart`, `LeadersOverTime`. D3 7.9.0 for the
  fingerprint's SVG cell layout/color scale (`d3.interpolateRgbBasis`,
  `d3.scaleSequential`) and for the homepage map's projection
  (`d3.geoMercator`, `d3.geoPath`). `topojson-client` + `world-atlas` supply
  the Indonesia coastline geometry for the map.
- **Maps**: PRD.md specifies Leaflet.js + CartoDB tiles; neither is
  installed or imported anywhere in `frontend/`. `IndonesiaMap.tsx` instead
  renders a raw inline `<svg>` with a d3-geo Mercator projection of a
  `MultiPolygon` coastline (Natural Earth 50m data via `world-atlas`), with
  city markers as plain SVG `<circle>` elements wrapped in Next `<Link>`s —
  no tile basemap, no pan/zoom.
- **Constraints observed in code**: static hosting (GitHub Pages,
  `output: "export"`); no backend at runtime in the shipped build (all data
  pre-baked JSON under `public/data/` and `data/static_export/`); numbers
  formatted to 1 decimal place everywhere via a single `fmt()` helper in
  `lib/format.ts`; `lang="en"` is hardcoded in `layout.tsx` with an inline
  comment stating Bahasa Indonesia i18n is deferred to a later phase; no
  mobile-specific code branch beyond responsive Tailwind classes.

## 3. Visual system as-built

**Color literals.** The system is centralized in `styles/tokens.css`
(reproduced above) and consumed almost exclusively through `var(--token)` or
Tailwind classes that resolve to those vars. Measured drift outside the
token file:

| Literal | Location | Context |
|---|---|---|
| `#12100c` | `app/layout.tsx:85` | `viewport.themeColor` (duplicates `--canvas`) |
| `#1D4E7A`, `#2B7CB8`, `#57A8DE`, `#9BD0F0` (×2 repeats) | `app/not-found.tsx` | decorative fake fingerprint row, 8 hardcoded swatches with 2 `null` gaps |
| `#fff` | `app/globals.css` (`::selection`) | text-selection color |
| `#000` ×2 | `app/globals.css` (`.canvas-grid` mask gradients) | |
| `rgb(62 147 208 / 0.22)` | `app/globals.css` (`.field:focus`) | focus-ring glow, matches `--rain-blue` but written as a literal, not `var()` |
| `rgb(226 102 31 / 0.16)`, `rgb(62 147 208 / 0.14)` | `app/globals.css` (`.canvas-aurora`) | hero background radial gradients |
| `rgb(247 243 234 / 0.035)` ×2 | `app/globals.css` (`.canvas-grid`) | background grid lines |
| `#1B1813` (in a comment) and `LINE_COLORS = ["#3E93D0","#E2661F","#45A05F","#CB4F9E"]` | `components/rankings/LeadersOverTime.tsx` | standalone 4-color categorical palette for the "ever held #1" chart lines, separate from the token system's series-1/series-2 pair |
| 5 six-stop hex ramps (precipitation, temp_max, hot_days, hot_days_local, dry_days) | `components/fingerprint/ramps.json` | fingerprint heatmap color ramps, dark→vivid, kept outside `tokens.css` in a dedicated data file |

**Fonts.** Three families, one each for a defined role: `--font-display`
(Fraunces, headings `h1`–`h3` and the `.eyebrow`/display type steps),
`--font-sans` (Inter, default body via `font-sans` on `body`), `--font-mono`
(JetBrains Mono, every number via `.font-numeric`, plus all chart tick
labels via `.svg-tick`). Fraunces is loaded with variable axes `SOFT`/`WONK`
and `h1`–`h3` set `font-variation-settings: "SOFT" 30, "WONK" 1`. Weights
used: 500 (`.eyebrow`), 600 (`.btn-primary`, headings via `font-semibold`
utility classes), no explicit 700/bold usage found beyond Tailwind's
`font-semibold`/`font-medium` utility classes.

**Sizes.** One linear type scale (13/14/15/16/18/22/28/36px, named
`2xs`–`3xl`) plus three fluid "editorial" clamp-based steps (`title`,
`hero`, `display`) for headlines. Tailwind's own default `fontSize` scale is
fully overridden, not extended, so no class can resolve outside this set.
SVG tick labels use a separate fixed `12px` (`--svg-tick-size`) because SVG
presentation attributes can't consume `var()` through `text-*` utilities —
documented directly in the token file. Exactly one arbitrary Tailwind
font-size literal exists in the whole component tree:
`text-[0.9em]` in `components/ui/TrendArrow.tsx`.

**Spacing.** A 4px-based ramp (`--space-1` through `--space-24`, i.e. 4px to
96px) mirrored by Tailwind's own numeric spacing scale; two named aliases
(`section` = 64px, `gutter` = 20px) exist for CSS-authored components.

**Border-radius.** Four steps: 6px (`sm`), 10px (default), 16px (`lg`), 22px
(`xl`), plus `rounded-full`/`999px` used ad hoc for pills (`.btn-primary`,
`.btn-ghost`, badges, scrollbar thumbs).

**Shadows.** Three steps (`--shadow-sm`, `--shadow`, `--shadow-lg`) plus a
fourth, `--rim` — a 1px inset highlight used on `.card` alongside `--shadow`
to fake a light source without a visible outline.

**Centralization verdict (factual):** colors, type scale, spacing, radius,
and shadow are all defined once in `tokens.css` and consumed via
Tailwind config or `var()`. The measured exceptions are: two duplicated
hex values (`--canvas` and `themeColor`), a handful of one-off `rgb()`
literals in `globals.css`'s decorative backgrounds/focus glow, the
404 page's decorative color array, and `LeadersOverTime`'s standalone
4-color palette. The fingerprint's 5 color ramps live deliberately outside
`tokens.css` in `ramps.json`, a data file rather than a stray literal.

**Dark mode.** Full and exclusive — `color-scheme: dark` is set globally,
there is one visual theme, and no `prefers-color-scheme` or theme-toggle
logic exists anywhere in the codebase.

## 5. Interaction & state

**Fingerprint (`ClimateFingerprint.tsx`):**
- Hover a cell → tooltip (month/year, formatted value + unit, ENSO phase
  line if overlay on) positioned near the cursor, flipping to the cursor's
  left near the right edge.
- Hover a year row → row highlights, other rows dim to `opacity:0.55`, and a
  callback drives a "hovered year" readout in the sidebar.
- `Escape` while the grid wrapper is focused clears hover/tooltip.
- No click handler on cells — hover-only, no drill-down (matches
  CLAUDE.md's "click cell → nothing in v1").
- The scroll container itself is `tabIndex={0}` (keyboard-focusable so
  horizontal overflow is reachable) but arrow-key cell navigation is not
  implemented — a real `<table>` marked `sr-only` provides the full
  data as an accessible/text alternative instead.
- `FingerprintPanel` adds: a 4-way segmented control (Rainfall/Temperature/
  Hot Days/Dry Days) that re-fetches data client-side, an ENSO-overlay
  toggle (custom pill+dot switch, off by default), and a sticky sidebar with
  a legend and hovered-year readout.

**Worked example (`WorkedExample.tsx`):** a draggable range-slider sets a
"hot day" temperature threshold, live-recomputing a highlighted day count
and drawing a dashed reference line across a day-by-day bar chart; state
syncs to a `?t=` URL param, debounced 300ms.

**Charts:** `ExtremeDaysChart` has a dropdown to pick among 8 metrics.
`PersonalBaseline` has a year-number input that recomputes a 10-year-window
delta and writes a `?since=` URL param. `RankingsTable`/`RecordsBoard` use
segmented controls to switch metric/granularity. `CompareResult` reads/reacts
to `?a=`/`?b=` query params.

**Map:** hover/focus a city marker → tooltip; click navigates to that
city's page via a real `<Link>`.

**Keyboard support found:** `CitySearch` and `CityPicker` implement full
ARIA-combobox/listbox keyboard patterns (Arrow keys, Enter, Escape,
`aria-activedescendant`); the fingerprint grid supports Escape-to-dismiss;
focus-visible states are custom-drawn in several places (`.field:focus`,
`.map-marker:focus-visible circle`) rather than left to browser defaults.
No drag/swipe/gesture handling beyond the native `<input type="range">`
slider in `WorkedExample`.

**Animation:** one CSS `@keyframes` (`rise` — fade + translateY(10px)→0,
600ms, custom cubic-bezier easing), applied via `.animate-rise` to hero/page
sections on load. Hover transitions (color, opacity, transform) are plain
CSS `transition` declarations (150–300ms) scattered across components, not a
JS animation library. All of it is disabled globally under
`prefers-reduced-motion: reduce` (durations forced to `0.01ms`,
`scroll-behavior: auto`) — a single blanket media query in `globals.css`.

**States present:**
- **Loading**: `city/[slug]/loading.tsx` (route-level pulse skeleton);
  `FingerprintPanel` dims the grid to `opacity:0.4` with `aria-busy` while
  re-fetching a variable; `ForecastContextLoader` renders nothing until its
  client fetch resolves.
- **Empty/no-result**: city page's "No data yet" block (with a CLI
  snippet); homepage's "No cities are available right now" card;
  `WhatMovedMost`'s "nothing cleared the movement floor" message;
  `SeasonLengthChart`'s "no detectable dry season" card;
  `RankingsTable`/`RecordsBoard`'s "Not enough data yet for this metric."
- **Error**: `CompareResult`'s "Couldn't load that comparison" text state;
  no route-level `error.tsx` boundary exists anywhere.
- **First-visit**: no onboarding/tour; the homepage hero itself (real
  fingerprint + real computed stat) functions as the first-visit
  explanation.
- **404**: dedicated `not-found.tsx`.
- A built, styled "low data coverage" warning (`NullDataWarning`) exists but
  is never rendered.

## 6. Weak points, stated plainly

- `RankingsTable` and `RecordsBoard` render their leaderboard/records data as
  tables and proportional horizontal bars — a table-of-numbers presentation
  for what is, at its core, spatial/ranked data across ~514 cities; there is
  no map-based or geographically-arranged view of rankings (the only map,
  `IndonesiaMap`, is homepage-only and shows region existence/data
  availability, not ranking values).
- `about/page.tsx`'s methodology and citation content is a
  `grid-[10rem_1fr]` label/content list — a generic sidebar-label +
  body-copy layout with no visual distinctiveness tying it to the climate
  domain (contrast with the fingerprint page's domain-specific rendering).
- `WorkedExample`'s day-by-day temperatures are shown as a small custom bar
  strip (16–50px bar height range) rather than integrated into any of the
  app's chart components — a bespoke, one-off numeric-to-visual mapping
  distinct from the shared `chart-ui.tsx` chrome used everywhere else.
- `NullDataWarning` was built to flag low-coverage regions per CLAUDE.md's
  Definition of Done, but is dead code with zero call sites — the
  low-coverage warning UX described in the project docs does not currently
  run anywhere in the app.
- No `error.tsx` at any route level — an unhandled render error in, e.g.,
  `CompareResult` or a chart component falls through to Next's default
  error handling rather than a designed in-app error state.
- Color-token drift: `LeadersOverTime`'s 4-line categorical palette and the
  404 page's decorative swatch array are hardcoded hex values sitting
  outside `tokens.css`, the file the rest of the system is centralized in.
- Contrast/accessibility notes found *addressed* in code (not gaps): all ink
  tokens are commented with measured WCAG ratios against their target
  surfaces; focus-visible styling is explicit and hand-drawn in multiple
  places (`:focus-visible` global outline, `.field:focus`,
  `.map-marker:focus-visible`); `prefers-reduced-motion` is honored globally;
  the fingerprint and map both ship non-SVG text alternatives
  (`sr-only` `<table>`, `<title>` elements) rather than relying on
  `aria-label` alone on the visual encoding. No contrast failures, missing
  focus states, keyboard traps, or unhandled reduced-motion cases were
  found in the files reviewed.
